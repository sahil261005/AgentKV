LLM serving · KV-cache memory · multi-agent workflows

When AI agents take turns,
the cache forgets the wrong thing.

AgentKV simulates the memory layer of an LLM server. It shows why the standard cache policy (LRU) throws away exactly the agent that runs next, and it builds and measures a fix that reads the workflow graph, learns it with a Markov chain, and prefetches from CPU memory.

Chapter 1

The problem in one picture

Four agents take turns calling the same model. The GPU only has room to cache three of them.

What LRU does

"Least Recently Used": throw out whatever was used longest ago.

    What AgentKV does

    Look at the workflow graph and throw out the agent that runs furthest in the future.

      💡
      In a loop, the agent used longest ago is exactly the one that runs next. LRU always evicts the worst possible thing. Evicting something right before it's needed, over and over, is called thrashing.
      Chapter 2

      The KV cache in 60 seconds

      An LLM turns every prompt token into a key and a value vector, in every layer. Storing them (the KV cache) lets the model skip recomputing the prompt. That first, expensive pass over a prompt is called prefill.

      What an agent's prompt looks like

      Every square is one block of 16 tokens. Memory is handed out in blocks (the vLLM / PagedAttention idea).

      Chapter 3

      Sharing prompts with a radix tree

      Prompts that start the same way share their cached blocks. SGLang stores them in a radix tree: each path from the root is a prompt, and shared beginnings are stored once. Send some prompts and watch the tree grow, share and split.

      Chapter 5

      Counting hops vs expecting steps

      AgentKV uses breadth-first search to count how many hops away each agent is. But when the Reviewer sends work back to the Coder some of the time, BFS calls Planner and Coder both "1 hop away". Our extension treats the workflow as a Markov chain and computes the expected number of steps instead. Drag the slider.

      From Reviewer, how far away is each agent?

      📐

      The one rule

      h(target) = 0
      h(u) = 1 + Σ P(u→w) · h(w)
      "Take one step, then add the average of where you land." NumPy solves all the equations at once.

      🧠

      It learns the graph

      It counts which step follows which, so nobody has to register a workflow. Before it has seen anything it behaves exactly like LRU, so it starts slow and improves.

      👥

      States are steps

      The first version modeled single agents and broke parallel fan-out (28.2% → 14.6%). Making a state "the group of agents running together" fixed it.

      Chapter 6

      Two memory tiers and prefetching

      A server has far more CPU RAM than GPU memory. Evicted prompts can be offloaded to the CPU instead of being deleted, and copied back about 20x cheaper than recomputing them. But a request that has to wait for that copy still stalls. Prefetching copies the next agent's prompt back before it runs.
